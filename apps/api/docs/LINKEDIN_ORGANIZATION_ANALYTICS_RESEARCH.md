# LinkedIn Organization / Page Analytics Research

Research date: 2026-07-16  
Scope set evaluated: `openid`, `profile`, `r_ads_reporting`, `r_organization_social`, `rw_organization_admin`, `w_member_social`, `r_ads`, `w_organization_social`, `rw_ads`, `r_basicprofile`, `r_organization_admin`, `email`, `r_1st_connections_size`

**Source-access note:** Some official Microsoft Learn pages displayed an “Access to this page requires authorization” banner in the browsing view. Their official public page text, endpoint schemas, permission tables, and examples were still available through LinkedIn/Microsoft Learn indexing and were cited here. Treat the linked pages as authoritative references, but re-check them in the authenticated LinkedIn Developer Portal/Marketing API documentation before implementation if a page remains inaccessible.

## Executive conclusion

For an authenticated member who is authorized for the target organization, the supplied scopes cover the main LinkedIn organization/page reporting surface:

- `r_organization_admin` is LinkedIn's read-oriented description for an organization's pages and reporting data, including follower, visitor, and content analytics. `rw_organization_admin` is the broader organization-admin permission and is the permission currently shown on the individual Follower, Page, and Share Statistics reference pages. The token has both, but the member must still have the required organization role and the application must be provisioned for the relevant LinkedIn product. ([Organization Access Control](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/organization-access-control-by-role?view=li-lms-2026-06), [Increasing Access](https://learn.microsoft.com/en-us/linkedin/marketing/increasing-access?view=li-lms-2026-06), [Organizations overview](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations?view=li-lms-2026-06))
- `r_organization_social` covers reading organization posts and organization video analytics, subject to the role requirements of those endpoints. ([Posts API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/posts-api?view=li-lms-2026-05), [Video Analytics API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/video-analytics-api?view=li-lms-2026-02))
- `r_ads_reporting` covers the separate `adAnalytics` reporting plane for advertising accounts. It does not turn organic Page Analytics into paid reporting, and the organization analytics endpoints do not replace ad reporting. ([Reporting](https://learn.microsoft.com/en-us/linkedin/marketing/integrations/ads-reporting/ads-reporting?view=li-lms-2026-06), [Organization Share Statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/share-statistics?view=li-lms-2026-05))

This is capability coverage, not a guarantee that every call will succeed. LinkedIn requires explicit application/product approval for Marketing APIs, a 3-legged member token, the member's role on the particular organization or ad account, a supported API version, and sometimes additional partner-tier access. ([Getting Access](https://learn.microsoft.com/en-us/linkedin/shared/authentication/getting-access), [Increasing Access](https://learn.microsoft.com/en-us/linkedin/marketing/increasing-access?view=li-lms-2026-06), [OAuth overview](https://learn.microsoft.com/en-us/linkedin/shared/authentication/authentication))

## Organic organization/page analytics

LinkedIn's organization statistics are keyed by an organization URN, normally `urn:li:organization:{id}`. Company Pages use organization URNs; Showcase Pages are represented as organization brands, although the current Organization Lookup documentation says the Organization Brand API has been deprecated and `urn:li:organizationBrand:XXX` is mapped to `urn:li:organization:XXX` from January 2024 onward. ([Organizations overview](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations?view=li-lms-2026-06), [Organization Lookup](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/organization-lookup-api?view=li-lms-2026-05))

All examples below use the current `/rest` resource paths. Requests should include `Authorization: Bearer ...`, `X-Restli-Protocol-Version: 2.0.0`, and a supported `Linkedin-Version: YYYYMM` header. ([API Versioning](https://learn.microsoft.com/en-us/linkedin/marketing/versioning?view=li-lms-2026-06))

### 1. Follower count and follower statistics

#### Total follower count

`GET /rest/networkSizes/{organizationUrn}?edgeType=COMPANY_FOLLOWED_BY_MEMBER` returns the organization's current follower count as `firstDegreeSize`. The current endpoint uses the uppercase `COMPANY_FOLLOWED_BY_MEMBER`; the older spelling `CompanyFollowedByMember` applies only to versions through `202304`. ([Organization Lookup — follower count](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/organization-lookup-api?view=li-lms-2026-05))

This is a point-in-time count. It is not the same as the demographic or time-series output from Follower Statistics, and the Follower Statistics endpoint no longer returns `totalFollowerCounts`; LinkedIn directs clients to Network Size for the total. ([Follower Statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/follower-statistics?view=li-lms-2026-04))

#### Follower Statistics endpoint

`GET /rest/organizationalEntityFollowerStatistics?q=organizationalEntity&organizationalEntity={organizationUrn}` supports:

- **Lifetime/demographic mode:** omit `timeIntervals`. It returns follower counts segmented by seven professional-demographic facets: association type/employee, country, function, industry, market area/geo, seniority, and follower's current organization staff-count range. Each facet is limited to the top 100 results. ([Follower Statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/follower-statistics?view=li-lms-2026-04))
- **Time-bound mode:** supply `timeIntervals.timeGranularityType` (`DAY`, `WEEK`, or `MONTH`) and a timestamp range. The response contains aggregate `organicFollowerGain` and `paidFollowerGain`; it is not segmented by demographic facet. LinkedIn documents availability from 12 months before the request date through two days before the request date, in UTC. ([Follower Statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/follower-statistics?view=li-lms-2026-04))
- **Counting nuance:** lifetime professional-demographic results are rolled up from organic and paid followers in `organicFollowerCount`; LinkedIn explicitly says not to interpret `paidFollowerCount` as the demographic paid total. ([Follower Statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/follower-statistics?view=li-lms-2026-04))

The endpoint reference lists `rw_organization_admin` and restricts the organization to a member with the `ADMINISTRATOR` role. The access-control reference separately describes `r_organization_admin` as the read/reporting permission. The supplied token has both, but the application should verify which permission the provisioned API product and selected version enforce. ([Follower Statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/follower-statistics?view=li-lms-2026-04), [Organization Access Control](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/organization-access-control-by-role?view=li-lms-2026-06))

### 2. Visitor/page analytics

#### Organization Page Statistics endpoint

`GET /rest/organizationPageStatistics?q=organization&organization={organizationUrn}` returns lifetime or time-bound page views and clicks. LinkedIn's current reference documents the following:

- **Lifetime mode:** omit `timeIntervals`; results include demographic facet arrays such as country/region, industry, geo/market, function, seniority, and staff-count range, plus `totalPageStatistics`. ([Organization Page Statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/page-statistics?view=li-lms-2025-08))
- **Time-bound mode:** add `timeIntervals.timeGranularityType` (`DAY` or `MONTH`) and a timestamp range. Results are aggregate records for each day or month in the range. ([Organization Page Statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/page-statistics?view=li-lms-2025-08))
- **Views:** overall, desktop, and mobile page views, with overview, jobs, Life at, and careers page categories where applicable. `allPageViews` and `overviewPageViews` are higher-level totals that include the comprehensive mobile and desktop traffic. ([Organization Page Statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/page-statistics?view=li-lms-2025-08))
- **Clicks:** desktop/mobile custom-button click-count fields are present in the response schema. Careers page views are only present for organizations with the paid Company Career Pages product. ([Organization Page Statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/page-statistics?view=li-lms-2025-08))

For a Showcase/brand page, the corresponding resource is `GET /rest/brandPageStatistics?q=brand&brand={brandUrn}` with the same lifetime/time-bound pattern. ([Organization Page Statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/page-statistics?view=li-lms-2025-08))

“Visitor analytics” is therefore represented by the Page Statistics resource in the organization analytics documentation; there is not a separate visitor-statistics endpoint in the cited organization analytics set. LinkedIn's permission table explicitly describes `r_organization_admin` as including follower, visitor, and content analytics. ([Organization Access Control](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/organization-access-control-by-role?view=li-lms-2026-06), [Organizations overview](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations?view=li-lms-2026-06))

### 3. Content/post analytics

#### Aggregate organization Share Statistics

`GET /rest/organizationalEntityShareStatistics?q=organizationalEntity&organizationalEntity={organizationUrn}` returns aggregate organization share statistics. With `timeIntervals`, it supports `DAY` or `MONTH` granularity and returns aggregate records for the selected range; without it, it returns lifetime statistics. The endpoint does not support pagination. ([Organization Share Statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/share-statistics?view=li-lms-2026-05))

The reported fields include `clickCount`, `commentCount`, `engagement`, `impressionCount`, `likeCount`, `shareCount`, and `uniqueImpressionsCount`. LinkedIn defines `engagement` as organic clicks, likes, comments, and shares over impressions. The endpoint has a rolling 12-month data window. ([Organization Share Statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/share-statistics?view=li-lms-2026-05))

The endpoint is explicitly **organic-only**: sponsored activity is excluded, and LinkedIn directs clients to Ad Analytics for sponsored activity. ([Organization Share Statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/share-statistics?view=li-lms-2026-05))

#### Per-post content reporting workflow

1. Retrieve organization post URNs with `GET /rest/posts?q=author&author={organizationUrn}` using `r_organization_social`. The Posts API replaces the older `ugcPosts` API and supports video, image, article, document, and other content categories documented by LinkedIn. ([Posts API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/posts-api?view=li-lms-2025-05))
2. Pass known `share` URNs or `ugcPost` URNs to Share Statistics for lifetime statistics for those specific posts. ([Organization Share Statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/share-statistics?view=li-lms-2026-05))
3. Do not assume per-post time series from this endpoint: LinkedIn explicitly says time-bound statistics are not supported for specific share or UGC-post queries. ([Organization Share Statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/share-statistics?view=li-lms-2026-05))

Social-action reads (likes/comments/reactions) are a related content-engagement surface, not a substitute for impression or engagement statistics. The current Social Metadata reference documents the newer feed permissions and warns that the older permission mapping was subject to a June 2023 migration. For the exact supplied token, use `r_organization_social` only where the selected endpoint's current permission table still permits it; otherwise the current Community Management feed permission may be required and is not in the supplied scope set. ([Social Metadata API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/social-metadata-api?view=li-lms-2026-02), [Network Update Social Actions](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/network-update-social-actions?view=li-lms-2026-03))

### 4. Organization video analytics

`GET /rest/videoAnalytics?q=entity&entity={ugcPostUrn}&type={type}&aggregation={aggregation}&timeRange={timeRange}` reports analytics for a video-containing organization UGC post. The endpoint requires `r_organization_social` and, per the current reference, the member must have the organization role `ADMINISTRATOR` or `DIRECT_SPONSORED_CONTENT_POSTER`. ([Video Analytics API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/video-analytics-api?view=li-lms-2026-02))

Available types are:

- `VIDEO_VIEW`: video view with a play/pause cycle of at least three seconds;
- `VIEWER`: unique viewers with engaged plays;
- `TIME_WATCHED`: total watch time in milliseconds;
- `TIME_WATCHED_FOR_VIDEO_VIEWS`: watch time for the at-least-three-second view cycles; LinkedIn says this corresponds to the Watch Time field in the UI.

Supported aggregation is `DAY`, `WEEK` (Sunday–Saturday), or `ALL` (default). A missing time range means lifetime aggregation; without a time range, daily/weekly responses default to 10 records when more than 10 records exist. `VIDEO_VIEW` and `VIEWER` data is unavailable after six months for the normal case, and `TIME_WATCHED_FOR_VIDEO_VIEWS` is also documented with six-month availability. ([Video Analytics API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/video-analytics-api?view=li-lms-2026-02))

Likes and comments are not returned by Video Analytics; retrieve those via the Social Actions/Social Metadata surface. ([Video Analytics API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/video-analytics-api?view=li-lms-2026-02))

## Paid advertising reporting: separate from Page Analytics

### Ad Analytics endpoint

`GET /rest/adAnalytics` uses `r_ads_reporting` and operates on sponsored ad accounts, campaigns, campaign groups, creatives, shares, conversions, and related advertising entities—not on an organization's organic Page Analytics record. The endpoint supports:

- **Analytics Finder:** one pivot, such as `ACCOUNT`, `CAMPAIGN_GROUP`, `CAMPAIGN`, `CREATIVE`, `SHARE`, `COMPANY`, `CONVERSION`, `SERVING_LOCATION`, or a professional-demographic/card pivot. ([Ad Analytics schema](https://learn.microsoft.com/en-us/linkedin/marketing/integrations/ads-reporting/ads-reporting-schema?view=li-lms-2026-06))
- **Statistics Finder:** up to three pivots. ([Reporting](https://learn.microsoft.com/en-us/linkedin/marketing/integrations/ads-reporting/ads-reporting?view=li-lms-2026-06))
- **Metrics:** impressions, clicks, landing-page/company-page clicks, spend in local currency/USD, reactions/likes/comments/shares, follows, conversions/leads, reach, and video starts/views/completions/quartiles/watch time, plus format-specific metrics. Metric availability depends on the pivot, ad format, and API version. ([Ad Analytics schema](https://learn.microsoft.com/en-us/linkedin/marketing/integrations/ads-reporting/ads-reporting-schema?view=li-lms-2026-06))
- **Time granularity:** daily/monthly/all-style reporting is selected through the finder query; the request uses a UTC `dateRange`. The current reference says performance data is retained for 10 years, professional-demographic data for two years, and daily data has a six-month retention behavior that can cause older `ALL` queries to round to month boundaries. ([Reporting](https://learn.microsoft.com/en-us/linkedin/marketing/integrations/ads-reporting/ads-reporting?view=li-lms-2026-06))

Important operational limits include no pagination for the current `adAnalytics` endpoint, a 15,000-element response limit, and a maximum of 20 explicitly requested metrics for Statistics Finder. Professional-demographic values are approximate, can be delayed 12–24 hours, are limited to the top 100 values per creative/day, and values with fewer than three events are dropped; video watch-time metrics can be delayed up to 48 hours. ([Reporting](https://learn.microsoft.com/en-us/linkedin/marketing/integrations/ads-reporting/ads-reporting?view=li-lms-2026-06))

`r_ads` and `rw_ads` identify/read or manage/read the member's ad accounts, but the Reporting reference names `r_ads_reporting` as the permission for reporting. The member must also have a role on the requested sponsored account; LinkedIn's account-role reference lists `VIEWER` as read-only and the manager/admin roles as having view campaign data and reports. ([Increasing Access](https://learn.microsoft.com/en-us/linkedin/marketing/increasing-access?view=li-lms-2026-06), [Account Access Controls](https://learn.microsoft.com/en-us/linkedin/marketing/integrations/ads/account-structure/account-access-controls?view=li-lms-2026-01))

### How to combine the two planes

Do not add `organizationalEntityShareStatistics` to `adAnalytics` totals as if they were the same metric family. Organic organization Share Statistics excludes sponsored activity; Ad Analytics reports paid delivery and paid/viral ad outcomes. If a post was promoted, use the sponsored creative/campaign/account report for its paid activity and the organization Share Statistics endpoint for the organic activity. ([Organization Share Statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/share-statistics?view=li-lms-2026-05), [Reporting](https://learn.microsoft.com/en-us/linkedin/marketing/integrations/ads-reporting/ads-reporting?view=li-lms-2026-06))

## Versioning, deprecation, and access caveats

- **Current version:** as of this research date, LinkedIn documents July 2026 as the latest Marketing API version, with header `Linkedin-Version: 202607`. Versioned releases are monthly and supported for at least one year. ([API Versioning](https://learn.microsoft.com/en-us/linkedin/marketing/versioning?view=li-lms-2026-06))
- **No unversioned calls:** LinkedIn expects versioned calls to include `Linkedin-Version`; the latest version is not silently applied. A deprecated version header returns an error. ([API Versioning](https://learn.microsoft.com/en-us/linkedin/marketing/versioning?view=li-lms-2026-06))
- **Migration timing:** the current versioning/recent-changes references show `202507` sunset on 2026-07-15 and `202508` scheduled to sunset on 2026-08-17. Do not build new calls against the older version headers shown in historical examples. ([API Versioning](https://learn.microsoft.com/en-us/linkedin/marketing/versioning?view=li-lms-2026-06), [Recent Marketing API Changes](https://learn.microsoft.com/en-us/linkedin/marketing/integrations/recent-changes?view=li-lms-2026-06))
- **Endpoint documentation mismatch:** current organization access-control documentation describes `r_organization_admin` as the read/reporting permission, while the individual Follower/Page/Share Statistics pages currently display `rw_organization_admin`. Since the supplied scope set contains both, the remaining checks are product provisioning, version behavior, organization role, and token consent—not adding another organization-admin scope. Validate against a real token in the target app because LinkedIn's product access and endpoint documentation are versioned. ([Organization Access Control](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/organization-access-control-by-role?view=li-lms-2026-06), [Follower Statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/follower-statistics?view=li-lms-2026-04), [Page Statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/page-statistics?view=li-lms-2025-08), [Share Statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/share-statistics?view=li-lms-2026-05))
- **Organization role:** the organization analytics overview says Follower, Share, and Page Statistics require an authenticated member with the `ADMINISTRATOR` role. The role reference also describes `ANALYST` as a Page-analytics UI role, but the cited endpoint pages still state `ADMINISTRATOR`; do not infer that a UI Analyst role is sufficient for every API endpoint. ([Organizations overview](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations?view=li-lms-2026-06), [Organization Access Control](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/organization-access-control-by-role?view=li-lms-2026-06))
- **Application approval:** LinkedIn says Marketing API products require approval/provisioning. The supplied OAuth scopes can be present in a token only after the app and member have the relevant access; scope strings alone do not grant access to arbitrary organizations or ad accounts. ([Getting Access](https://learn.microsoft.com/en-us/linkedin/shared/authentication/getting-access), [Increasing Access](https://learn.microsoft.com/en-us/linkedin/marketing/increasing-access?view=li-lms-2026-06))
- **Token type and re-consent:** these are member-authorized resources. The 3-legged OAuth guide says scopes must be explicitly requested and that changing requested scopes requires re-authentication. ([Authorization Code Flow](https://learn.microsoft.com/en-us/linkedin/shared/authentication/authorization-code-flow))
- **Privacy/accuracy:** professional-demographic ad metrics are approximate and suppressed/limited for privacy. Do not treat them as exact member-level counts or billing-grade values. ([Reporting](https://learn.microsoft.com/en-us/linkedin/marketing/integrations/ads-reporting/ads-reporting?view=li-lms-2026-06), [Ad Analytics schema](https://learn.microsoft.com/en-us/linkedin/marketing/integrations/ads-reporting/ads-reporting-schema?view=li-lms-2026-06))

([Follower Statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/follower-statistics?view=li-lms-2026-04)) |
| Page visitors/views/clicks | `GET /rest/organizationPageStatistics` | `r_organization_admin` / `rw_organization_admin` | DAY/MONTH time series; lifetime facet output. ## Bottom line

With the exact scopes listed, the expected usable set is: organization follower count and follower statistics; organization Page visitor/view/click statistics; organic organization/share/post performance; per-video organic analytics for organization video posts; and paid ad-account reporting through `adAnalytics`. The principal blockers are not missing scopes in the supplied set: they are LinkedIn app/product approval, member role on each organization/ad account, the `r_organization_admin` versus `rw_organization_admin` version/documentation distinction, current API version headers, endpoint retention windows, and the fact that organic and paid metrics are separate products and should be stored/reported separately.
